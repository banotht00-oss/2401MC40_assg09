Technical Report: xv6 Virtual Memory and Page Replacement Implementation
This project implements three key virtual memory enhancements and page replacement evaluations in the xv6 operating system (x86 architecture).

For Question 1, we implemented the vmprint system call to inspect process memory maps. By writing vmprint(pde_t *pgdir) in vm.c, the kernel traverses the two-level page directory for entries below KERNBASE, extracting valid virtual-to-physical translations along with their protection flags (P, W, and U). It tracks both total valid user pages and page-table pages. The companion user program, pttest.c, invokes vmprint() at startup and immediately after expanding the process heap via sbrk(4 * 4096). The resulting terminal output confirms that exactly four new user pages are allocated and mapped upon heap expansion.

For Question 2, we introduced lazy memory allocation to optimize resource usage. We modified sys_sbrk() in sysproc.c so that positive allocations only increment myproc()->sz without calling allocuvm(), and adjusted deallocuvm() and copyuvm() in vm.c to gracefully skip unallocated pages instead of triggering a kernel panic. In trap.c, we added a handler for page faults (T_PGFLT) utilizing rcr2(). When a fault occurs within the valid process size limit (sz), the kernel dynamically allocates a zeroed physical page using kalloc() and memset(), maps it via mappages() with PTE_W | PTE_U permissions, and updates a process fault counter (numfaults). The test program faulttest.c allocates memory for 32 pages (sbrk(32 * 4096)), writes to exactly 5 distinct pages, and verifies via the getfaults() system call that precisely 5 page faults were handled. It also demonstrates that out-of-bounds accesses safely terminate only the offending process without destabilizing the kernel.

For Question 3, we developed a user-space simulation program, pagerepl.c, to evaluate First-In, First-Out (FIFO) and Least Recently Used (LRU) page replacement algorithms. The program accepts a frame count and reference string, maintaining frame states step-by-step while reporting individual hits and faults. Testing with 3 frames on the standard reference string (7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1) yielded 15 page faults for FIFO and 12 for LRU. Running both algorithms across 3, 4, and 5 frames produced a comprehensive comparison table confirming that LRU consistently outperforms FIFO by achieving higher hit ratios and fewer page faults under identical workloads
